# Running Parameter Golf on RunPod

Step-by-step guide for a fresh Ubuntu 22.04/24.04 environment (e.g. a RunPod container).

---

## Quick Start (3 commands after SSH)

```bash
git clone https://github.com/<your-fork>/parameter-golf.git
cd parameter-golf
bash setup.sh
```

Then download data and train (see steps below).

---

## 1. Launch a RunPod Pod

1. Go to [console.runpod.io/deploy](https://console.runpod.io/deploy).
2. Deploy using the official Parameter Golf template:
   `https://console.runpod.io/deploy?template=y5cejece4j&ref=nl2r56th`
   - Enable **SSH terminal access**.
   - Leave other settings at defaults.
3. Once running, SSH in. You will land in `/workspace/`.

> **Tip:** For iterating, use a 1×H100 (cheaper). Final leaderboard submissions must run in under 10 min on 8×H100 SXM.

---

## 2. Clone the Repository

```bash
cd /workspace
git clone https://github.com/<your-fork>/parameter-golf.git
cd parameter-golf
```

Replace `<your-fork>` with your GitHub username/org. To use the upstream repo:
```bash
git clone https://github.com/openai/parameter-golf.git
```

---

## 3. Run Setup

```bash
bash setup.sh
```

This script (non-interactive, safe to run as root):

- Installs system packages (`curl`, `git`, `build-essential`, etc.)
- Installs **Node.js LTS** via NodeSource
- Installs **Claude Code** globally (`npm install -g @anthropic-ai/claude-code`)
- Creates a Python virtual environment at `.venv/`
- Installs Python dependencies from `requirements.txt`

> On the official RunPod template, PyTorch with CUDA is pre-installed. `setup.sh` detects this and skips reinstalling torch to avoid downgrading CUDA support.

---

## 4. Activate the Virtual Environment

```bash
source .venv/bin/activate
```

Add this to your shell profile if you want it persistent:
```bash
echo 'source /workspace/parameter-golf/.venv/bin/activate' >> ~/.bashrc
```

---

## 5. Download the Dataset

```bash
python3 data/cached_challenge_fineweb.py --variant sp1024
```

This downloads:
- Full validation split (`fineweb_val_*`) — required for scoring
- 80 training shards (≈8B tokens) by default

For a smaller smoke-test subset:
```bash
python3 data/cached_challenge_fineweb.py --variant sp1024 --train-shards 1
```

Files land in `data/datasets/fineweb10B_sp1024/` and `data/tokenizers/`.

---

## 6. Run Training

### Single GPU (1×H100)

```bash
RUN_ID=my_run \
DATA_PATH=./data/datasets/fineweb10B_sp1024/ \
TOKENIZER_PATH=./data/tokenizers/fineweb_1024_bpe.model \
VOCAB_SIZE=1024 \
torchrun --standalone --nproc_per_node=1 train_gpt.py
```

### Multi-GPU (8×H100)

```bash
RUN_ID=my_run_8gpu \
DATA_PATH=./data/datasets/fineweb10B_sp1024/ \
TOKENIZER_PATH=./data/tokenizers/fineweb_1024_bpe.model \
VOCAB_SIZE=1024 \
torchrun --standalone --nproc_per_node=8 train_gpt.py
```

### Useful environment variables

| Variable | Default | Description |
|---|---|---|
| `RUN_ID` | auto UUID | Name for this run's log file |
| `DATA_PATH` | required | Path to tokenized shards |
| `TOKENIZER_PATH` | required | Path to `.model` tokenizer file |
| `VOCAB_SIZE` | required | Vocabulary size (e.g. `1024`) |
| `MAX_WALLCLOCK_SECONDS` | 600 | Set to `0` for unlimited |
| `VAL_LOSS_EVERY` | 0 | Print val loss every N steps (0 = end only) |
| `VAL_BATCH_SIZE` | 8192 | Tokens per validation batch |
| `SIZE_ONLY` | 0 | Set to `1` to measure artifact size without training |

---

## 7. Check Artifact Size

```bash
SIZE_ONLY=1 \
DATA_PATH=./data/datasets/fineweb10B_sp1024/ \
TOKENIZER_PATH=./data/tokenizers/fineweb_1024_bpe.model \
VOCAB_SIZE=1024 \
torchrun --standalone --nproc_per_node=1 train_gpt.py
```

The artifact limit is **16,000,000 bytes** (decimal 16 MB) for code + compressed weights combined.

## 9. Persisting Work Between Sessions

RunPod containers are **ephemeral** — the filesystem is wiped when the pod stops. To persist your work:

- **Commit and push to git** before stopping the pod:
  ```bash
  git add -A
  git commit -m "checkpoint: describe changes"
  git push origin runpod
  ```
- Model weights (`final_model.pt`, `final_model.int8.ptz`) are `.gitignore`d because they are large binaries regenerated by training. If you want to preserve a checkpoint, upload it to cloud storage (S3, HuggingFace Hub, RunPod volume) manually.
- The dataset (`data/datasets/`) is also `.gitignore`d; re-run `cached_challenge_fineweb.py` each session or mount a RunPod **Network Volume** to avoid re-downloading.

### Using a RunPod Network Volume (recommended for data)

1. Create a Network Volume in the RunPod console (at least 100 GB).
2. Attach it to your pod at `/workspace/data`.
3. Run the dataset download once; it persists across pod restarts.

## 10. Troubleshooting

**`torch` not found after `setup.sh`**
Activate the venv: `source .venv/bin/activate`

**CUDA not available (`torch.cuda.is_available()` returns False)**
The RunPod template pre-installs CUDA torch. If you ran `setup.sh` on a bare Ubuntu machine without a GPU, install torch with CUDA manually:
```bash
pip install torch --index-url https://download.pytorch.org/whl/cu124
```

**`torchrun` not found**
It is installed alongside `torch` inside the venv. Make sure the venv is activated.

**Node.js / Claude Code not found**
Re-run `bash setup.sh` — it is idempotent and safe to run multiple times.

**Dataset download is slow**
Use `--train-shards 1` for quick smoke tests. Mount a Network Volume to avoid re-downloading.

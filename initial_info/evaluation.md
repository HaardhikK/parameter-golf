# Parameter Golf: Official Rules & Evaluation

## Core Constraints
* **Compute Budget:** Training must complete from scratch in under 10 minutes (enforced by a 600.0 second wall-clock cap) on 8×H100 GPUs.
* **Artifact Size Limit:** The total submission size must be ≤ 16,000,000 bytes.
* **Evaluation Metric:** Models are evaluated on Bits Per Byte (BPB) on a fixed FineWeb validation set. A lower BPB indicates a better compressor/predictor. This metric is tokenizer-agnostic.
* **Dataset:** Models must be trained exclusively on the provided FineWeb export (roughly 8–10B training tokens and a fixed validation split) generated by the repo's data scripts.

## Artifact Sizing Breakdown
* The 16 MB limit encompasses the entire submission, including the code, compressed weights, tokenizer, and configuration.
* The artifact size is strictly enforced after training during the serialization step.
* The total size is calculated as the sum of `quant_file_bytes` (the model quantized to int8 and compressed with zlib) and `code_bytes` (the length of the encoded utf-8 code).

## Environment & Network Rules
* The evaluation environment strictly prohibits external network calls.
* The entire submission must be fully self-contained.
* Downloading additional data, code, or pinging online APIs during evaluation will fail the run.

## Submission & Evaluation Process
* **Submission Format:** All entries must be submitted via a public GitHub Pull Request to the `openai/parameter-golf` repository.
* **Required Contents:** The PR must include your model code, configuration, training script, the weights/checkpoints strictly encoded into the 16 MB artifact, along with required logs and descriptions.
* **Automated Scoring:** Submissions are automatically re-run through GitHub Actions and evaluation workflows connected to the leaderboard.
* **Attempts:** Participants are allowed to submit multiple PRs and iterate during the competition.
